# 本機節點架構總覽

狀態：已確認的設計決策（2026-09-30）。各子專案另有獨立規格；本文件只記錄跨子專案共用的決策。

## 目標

讓客戶在自己的電腦或伺服器安裝「本機節點」，以網頁主控台操作問卷、分析、本地 LLM 與改善追蹤；
回覆原文與分析運算留在客戶端，雲端只負責收件轉接、控制資訊與遠端查看。產品由客戶自行操作。

## 部署模式

同一套 Django 程式碼，以單一設定值 `DEPLOYMENT_MODE` 區分（`cloud` 或 `node`）；不維護第二個專案。

| | 雲端（`cloud`，Render） | 本機節點（`node`） |
|---|---|---|
| 用途 | 公開首頁與展示、顧客填問卷、遠端查看已發布結果、加密收件匣轉接 | 客戶的主控台：問卷、分析、本地 LLM、改善任務、備份 |
| 登入者 | 管理者與填問卷的顧客 | 只有客戶的員工 |
| 資料庫 | Supabase | 本機 SQLite（WAL），可改 PostgreSQL |
| Google 登入 | 網頁應用程式用戶端 | 桌面應用程式用戶端＋PKCE（僅本機） |
| 機密 | 環境變數 | Windows 認證管理員（`keyring`） |

只在某一模式有意義的功能以模式開關啟用：`/setup/`、區域網路、防火牆、本機備份只在 `node`；公開註冊、公開首頁、
顧客填答只在 `cloud`。分析、問卷管理、結果頁、設計系統、帳號系統、工作佇列為兩模式共用。CI 以兩種模式各跑一次測試。

## 回覆如何進入本機

```
客戶在主控台設計問卷 ──只同步問卷定義──> 雲端
顧客在雲端登入並填答 ──瀏覽器端以節點公鑰加密──> 雲端收件匣（只存密文）
本機節點主動連出拉取 ──解密、寫入本地資料庫、回報收訖──> 雲端刪除該筆
```

- 本機節點不開放任何對外連接埠；本機離線時回覆暫存於收件匣（保存上限，例：30 天），網頁提示節點離線天數。
- 顧客帳號在雲端（問卷維持 login-only）；本機節點只有員工帳號。
- 改善通知由節點解密後產生內容，經寄信服務送出（細節於子專案 8）。
- 補充收件方式：店內平板直連本機（需區域網路模式）、匯入其他問卷工具的檔案（沿用現有匯入器）。

Supabase 在此架構下的角色：收件匣（短暫、密文）、控制中心（帳號、組織、問卷定義、裝置註冊、工作狀態，為雲端正本）、
結果快取（本機為正本，可選擇不上傳）。

## 組織與權限

- 一個本機節點服務一家公司（組織）；組織底下只有「部門」一層。每份問卷只屬於一個部門，跨部門查看需明確分享。
- 權限＝角色（能做什麼）×範圍（組織或部門）。一人可在不同部門擔任不同角色。
- 所有頁面透過同一個查詢函式取得可存取的問卷（例：`accessible_surveys(user, capability)`），不在各頁各自判斷。

## 改善任務（閉環回饋）

改善項目下可拆多個任務，各自指派執行者。任務流程：已指派 → 執行中 → 已提交（待驗收）→ 已完成；可退回並附原因。
全部任務驗收完成後，改善項目才能標為已完成並寄送顧客通知。執行者頁面以手機操作為主（我的任務、任務詳情）；
主管另有待驗收清單；逾期任務在總覽提醒。第一版通知執行者用站內與 Email，LINE 之後再加。

## 存取與網路

- 預設只接受本機連線（`127.0.0.1`）。擁有者可開放單一網路介面到區域網路，強制 HTTPS（自簽憑證＋指紋核對；
  之後可升級為廠商網域正式憑證），並需重新驗證身分與兩步驟驗證。
- 遠端存取經雲端轉接，不要求客戶開放連接埠。
